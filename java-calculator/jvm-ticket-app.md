# JVM, JDK and JRE – Java Ticket Booking Application

## 1. Introduction

Java is a platform-independent programming language. One of its important features is that Java applications can run on different operating systems without changing the original source code.

Java achieves this using:

- JDK (Java Development Kit)
- JRE (Java Runtime Environment)
- JVM (Java Virtual Machine)

When we write a Java program, it is compiled into bytecode. The JVM executes this bytecode on the operating system.

This document explains these concepts using a simple Ticket Booking application.

## 3. Role of JDK, JRE and JVM

### 3.1 JDK – Java Development Kit

JDK stands for Java Development Kit.

It provides the tools required to develop, compile, debug, and run Java applications.

Important JDK tools include:

- javac: Compiles Java source code into bytecode.
- java: Launches the Java application.
- javadoc: Generates documentation.
- jdb: Java debugger.

**Ticket Booking Example:**

Suppose we are developing a Ticket Booking application.

We create a file named `TicketBooking.java`.

The JDK provides the `javac` compiler to compile this source code:

```bash
javac TicketBooking.java
```

After successful compilation, Java generates:

```text
TicketBooking.class
```

**In simple words:** JDK is used by Java developers to create and compile Java applications.

### 3.2 JRE – Java Runtime Environment

JRE stands for Java Runtime Environment.

It provides the environment required to run Java applications.

Conceptually, a traditional JRE consists of:

- JVM
- Java class libraries
- Supporting runtime components

**Ticket Booking Example:**

After compiling `TicketBooking.java`, we need a Java runtime environment to execute the generated bytecode.

The runtime provides the JVM and required Java libraries.

For example:

```bash
java TicketBooking
```

The Java runtime starts the application.

**In simple words:** JRE provides the environment needed to run Java applications.

Note: Modern Java distributions commonly provide a JDK rather than a separately installed JRE. A custom runtime can also be created using tools such as `jlink`.

### 3.3 JVM – Java Virtual Machine

JVM stands for Java Virtual Machine.

It is responsible for loading, verifying, and executing Java bytecode.

Important JVM components include:

1. Class Loader
2. Bytecode Verifier
3. Runtime Memory Areas
4. Execution Engine
5. Garbage Collector

**Ticket Booking Example:**

When a customer opens a ticket booking application, the JVM loads the compiled classes and executes the application instructions.

For example, the JVM executes logic for:

- Searching available tickets.
- Checking seat availability.
- Calculating ticket prices.
- Processing booking requests.

**In simple words:** JVM executes Java bytecode and makes Java platform-independent.

## 4. TicketBooking.java Example

Let's create a simple Java ticket booking application.

### Source Code

Create a file named `TicketBooking.java`:

```java
public class TicketBooking {

    public static void main(String[] args) {

        String customerName = "Pratiksha";
        String movieName = "Java Movie";
        int numberOfTickets = 2;
        double ticketPrice = 200.0;

        double totalAmount = numberOfTickets * ticketPrice;

        System.out.println("===== Ticket Booking =====");
        System.out.println("Customer: " + customerName);
        System.out.println("Movie: " + movieName);
        System.out.println("Tickets: " + numberOfTickets);
        System.out.println("Total Amount: Rs. " + totalAmount);
        System.out.println("Booking Successful!");
    }
}
```

### Step 1: Compile the Java program

Open the terminal and execute:

```bash
javac TicketBooking.java
```

The compiler generates:

```text
TicketBooking.class
```

### Step 2: Execute the program

Run:

```bash
java TicketBooking
```

### Expected Output

```text
===== Ticket Booking =====
Customer: Pratiksha
Movie: Java Movie
Tickets: 2
Total Amount: Rs. 400.0
Booking Successful!
```

### Step 3: Understand the execution

1. The developer writes `TicketBooking.java`.
2. The JDK provides the `javac` compiler.
3. The compiler converts the source code into bytecode.
4. The generated bytecode is stored in `TicketBooking.class`.
5. The JVM loads and verifies the bytecode.
6. The JVM execution engine runs the application.

## 5. How the Same .class File Runs on Windows, macOS and Linux

Java supports platform independence through bytecode and the JVM.

When we compile a Java program, the compiler generates platform-independent bytecode.

The same `.class` file can run on different operating systems if they have a compatible JVM and required dependencies.

### Platform Independence Diagram

```text
                TicketBooking.java
                        |
                        |
                       javac
                        |
                        |
                TicketBooking.class
                    (Bytecode)
                        |
          --------------+--------------
          |             |             |
          |             |             |
       Windows         macOS         Linux
          |             |             |
      Windows JVM    macOS JVM    Linux JVM
          |             |             |
          --------------+--------------
                        |
                        |
               Ticket Booking App
                    Executes
```

### Explanation

**Windows:**

The Windows JVM loads the `.class` file and executes its bytecode on Windows.

**macOS:**

The macOS JVM loads the same `.class` file and executes it on macOS.

**Linux:**

The Linux JVM loads the same `.class` file and executes it on Linux.

The source code and compiled bytecode do not need to be rewritten for each operating system.

### Example

Compile once:

```bash
javac TicketBooking.java
```

Generated file:

```text
TicketBooking.class
```

Copy the `.class` file to another computer that has a compatible Java runtime.

Execute it using:

```bash
java TicketBooking
```

**Important:** The `.class` file is portable, but the JVM itself is platform-specific. Each operating system needs its own compatible JVM implementation. Native libraries, external dependencies, and operating-system-specific code may also affect portability.

## 6. Difference Between Compiler and Interpreter

A compiler and an interpreter are used to translate or execute programming instructions.

### Compiler

A compiler translates source code into another form before execution.

In Java:

- `javac` compiles `.java` source files.
- It generates `.class` bytecode files.

Example:

```bash
javac TicketBooking.java
```

### Interpreter

An interpreter executes instructions at runtime.

The JVM can interpret Java bytecode instruction by instruction.

This allows Java programs to execute without directly translating all bytecode into native machine code beforehand.

### Comparison

| Compiler | Interpreter |
|---|---|
| Translates source code into another form. | Executes instructions at runtime. |
| Java uses javac to compile source code. | JVM can interpret bytecode. |
| Produces `.class` bytecode in Java. | Executes the generated bytecode. |
| Detects many compilation errors before execution. | Runtime errors can occur during execution. |

## 7. What is JIT Compiler?

JIT stands for Just-In-Time Compiler.

It is a component of the JVM execution engine.

The JIT compiler improves application performance by compiling frequently executed bytecode into native machine code at runtime.

### How JIT Works

1. JVM loads the compiled Java bytecode.
2. The interpreter starts executing bytecode.
3. JVM monitors frequently executed code.
4. The JIT compiler identifies frequently executed methods or code sections.
5. It compiles those sections into native machine code.
6. The JVM can execute the optimized native code for better performance.

### JIT Architecture Diagram

```text
       Java Source Code
              |
            javac
              |
        Bytecode (.class)
              |
             JVM
              |
       Execution Engine
              |
       -----------------
       |               |
   Interpreter      JIT Compiler
       |               |
   Bytecode        Native Machine
   Execution           Code
       |               |
       -------+---------
              |
       Program Execution
```

### Banking Example

Imagine a banking application that processes thousands of account balance enquiries.

The balance enquiry method may execute very frequently.

The JVM can identify this frequently executed method and compile it into optimized native machine code using the JIT compiler.

This can improve performance during application execution.

**Benefits of JIT:**

- Improves runtime performance.
- Optimizes frequently executed code.
- Reduces repeated interpretation overhead for optimized code.
- Helps Java applications handle demanding workloads.

|---|---|---|---|
| Full Form | Java Development Kit | Java Runtime Environment | Java Virtual Machine |
| Purpose | Develop and run Java applications | Run Java applications | Execute Java bytecode |
| Compiler | Includes javac | Not normally included | Does not compile source code |
| Java Libraries | Includes development and runtime libraries | Provides runtime libraries | Uses runtime support |
| Usage | Developers | Application users | Executes bytecode |

## 9. Key Takeaways

- JDK is used to develop, compile, and run Java applications.
- JRE provides the runtime environment for Java applications.
- JVM loads, verifies, and executes Java bytecode.
- `javac` converts Java source code into bytecode.
- Bytecode can run on Windows, macOS, and Linux using compatible JVM implementations.
- The JVM can interpret bytecode and use JIT compilation to improve performance.
- Java platform independence is based on bytecode and platform-specific JVM implementations.

## 10. Conclusion

JDK, JRE, and JVM are important parts of the Java platform.

Using the Ticket Booking example, we can understand how Java source code is compiled into bytecode and executed by the JVM.

The JVM makes Java platform-independent by allowing the same compiled bytecode to run on different operating systems through compatible JVM implementations.

The interpreter and JIT compiler work together within the JVM execution engine to execute Java programs and improve runtime performance.

Understanding these concepts provides a strong foundation for Java development and technical interviews.
