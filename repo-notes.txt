Git manages files across three main states as you modify and save changes: the working directory, the staging area, and the repository.
Using a file named expenses.txt, here is how a change moves through each state:

1. Working Directory (Modified)

• What it is: The local folder on your computer where you actively view and edit files.
• Example: You open expenses.txt and add a new line: "Coffee: $5". Git notices the file has changed compared to your last saved version, so it marks expenses.txt as modified.

2. Staging Area (Staged)

• What it is: A preparation zone (also called the index) where you gather the exact changes you want to include in your next permanent snapshot.
• Example: You run git add expenses.txt. Your "Coffee: $5" update is now staged. If you also edited another file (notes.txt) but didn't stage it, Git will ignore notes.txt during the next save.

3. Repository (Committed)

• What it is: The hidden .git folder where Git permanently stores snapshots of your project history.
• Example: You run git commit -m "Add coffee expense". Git takes everything currently in the staging area and saves a permanent snapshot in the repository, marking expenses.txt as committed
